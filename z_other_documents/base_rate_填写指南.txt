# base_rate 填写指南　Base Rate Filling Guide

> base_rate = 在看到任何评论之前，你对这部片**最终 RT 分数**的预期。
> 它进入贝叶斯先验，代表"开盘前我赌它大概落在哪"。
>
> base_rate = your expectation of the movie's **final RT score** *before* seeing
> any reviews. It seeds the Bayesian prior — "where I'd bet it lands, pre-embargo."

---

## 核心认知　Core principle

**base_rate 没有唯一正确答案，它是建模判断，不是可查到的客观常数。**
同一部片，用"导演前作"和用"同类型均分"可能得出不同值，两个都不算错，只是
参照系不同。所以目标是**用对参照系 + 数值合理**，不是精确到个位数。

**base_rate has no single correct value — it's a modeling judgment, not a
lookup constant.** Aim for the *right reference class* and a *reasonable number*,
not decimal precision.

---

## 铁律：只能用"这部片之前"的信息　The one hard rule

**base_rate 必须独立于这部片自己的结果。**
只能用开盘前就存在的信息（前作分数、导演历史、类型均分）。**绝不能**用这部片
自己的评论或最终分数反推——那是数据泄漏，会让回测作弊。

即使你已经知道某片最终 77 分，填 base_rate 时也要**假装不知道**，只用前作/
导演/类型预判。回测要还原的就是"开盘前的认知状态"。

**Never derive base_rate from the movie's own reviews or final score** — that's
data leakage and makes the backtest cheat. Even if you know the answer, pretend
you don't; use only pre-embargo information.

---

## 优先级规则（从强到弱）　Priority ladder (strongest → weakest)

每部片从第 1 条往下走，能用强信号就别用弱的。
Walk each movie top-down; use the strongest signal available.

### 第 1 优先：直系前作　Direct predecessors
有明确续集关系的，用前作均分。最强信号——同系列的团队、品控、受众连续。
- 玩具总动员 5 → 玩具总动员 1–4 均分
- 阿凡达：火与烬 → 阿凡达 1–2 均分
- 疯狂动物城 2 → 疯狂动物城 1

### 第 2 优先：同导演近期作品　Same director, recent work
没有直接前作（原创片、系列首部），用导演**最近 3–5 部**均分。
导演是质量最稳定的预测因子之一。注意用"近期"——别用 20 年前的，导演会变。

### 第 3 优先：核心主创 / 制片厂 / IP　Key creatives / studio / IP
导演也难找参照时：
- 同编剧、或同制片厂的同类产品（皮克斯动画、A24 文艺片，各有稳定质量带）
- 同 IP 宇宙（漫威某阶段的片子口碑水位相近）

### 第 4 优先（兜底）：同类型 / 同题材历史均分　Genre baseline (fallback)
完全原创、无任何关联的小片（如 Primate）：
用同类型片的大致历史均分。恐怖片、喜剧、剧情片各有不同的平均 Tomatometer。
最弱的信号，但总比瞎填 90 强。

---

## 操作流程　Workflow

每部片走一遍这个判断树：

```
有直系前作？
  ├─ 有 → 用前作均分（第1优先）
  └─ 无 → 导演近期有几部片？
          ├─ 有 → 用导演近 3–5 部均分（第2优先）
          └─ 难找 → 有同制片厂/IP/类型参照？
                    ├─ 有 → 用它（第3优先）
                    └─ 无 → 同类型历史均分兜底（第4优先）
```

---

## 填写时记下依据　Record your reasoning

填的时候在 config 注释里记一句用了什么参照，方便日后回查：

```python
"toy_story_5": {
    "base_rate": 98.5,   # 玩具总动员 1–4 均分（直系前作）
    ...
},
"primate": {
    "base_rate": 65,     # 无前作，惊悚类型历史均分兜底
    ...
},
```

回测若发现某片预测异常，你能立刻查是不是 base_rate 参照选错了。

---

## 重要：不用纠结精确值　Don't obsess over precision

base_rate 通过 prior_strength 进入先验，而 prior_strength 是个**小数**（如 10，
相当于"假装提前看了 10 条评论"）。一旦真实评论积累到几十上百条，**先验影响被
实际数据稀释得很小**：

- 解禁初期（评论少，如 20 条）：base_rate 影响较大
- 评论多了（100+ 条）：base_rate 几乎不影响，数据自己说话

所以**填到"参照系正确、数值合理"即可，不必精确到个位**。95 还是 96 的差异，
评论积累后基本被冲掉。把精力放在"用对参照系"，不是"精确到个位数"。

而且 **prior_strength 本身是回测要校准的**。回测若发现它最优值很小（先验该
很弱），base_rate 的精度就更不重要。先搭回测，很多"参数要多精确"的纠结，
回测会自动给答案。

---

## 速查　Quick reference

| 情况 | 用什么 |
|---|---|
| 续集 / 有前作 | 前作均分 |
| 原创但导演有名气 | 导演近 3–5 部均分 |
| 导演也难找 | 同制片厂 / IP / 同类型 |
| 完全原创小片 | 同类型历史均分兜底 |
| 任何情况 | **绝不能用本片自己的评论/最终分** |

---

*base_rate 是回测的输入（事先查的事实）；prior_strength 和 drift 是回测的产出
（校准出来的）。三者别混。*
*base_rate is a backtest input (a fact you look up); prior_strength and drift are
backtest outputs (calibrated). Don't conflate them.*
